## 2. 项目目标与边界

主场景由用户确定为运输和仓储。问题是：正常工况变化会改变传感器分布，单一正常参考容易误报；需要根据当前已知工况，对每个传感器给出观测一致性评分。

研究问题依次为：RQ1，工况参考能否减少合法状态的误报；RQ2，逐通道评分能否定位污染并限制牵连；RQ3，评分作为额外输入是否改善相同预测器的质量预测。RQ1/RQ2已有模拟证据；RQ3没有实验结果。三个问题的结论不能互相替代。

当前示意数据是温度K、相对湿度percent_RH、振动mm_per_s，工况为仓储、平稳运输、颠簸运输；时间是抽象采样步。参数未经具体石化产品标定，环境传感器也不自动代表货物内部状态。生产推广、物理动力学、区块链、可视化平台及生产部署均不在本次范围。

## 3. 已实现的方法与使用流程

### 3.1 数据和参考

完整序列互斥划分train_fit、train_cal、val、test。train_fit拟合标准化、中心和Ledoit–Wolf收缩协方差；另一组train_cal校准逐工况逐通道q99。clean、observed及污染mask分开保存，评分函数只接收观测、当前可用工况记录和训练模型。

边际残差衡量单个通道偏离当前工况分布的程度；条件残差还利用同一时刻其他通道的统计关系，因此可能提高弱偏置检出，也可能牵连干净通道。

### 3.2 默认版本

默认固定为**regime_marginal + EWMA，alpha=0.2，q99，reset=true**。有符号残差先因果累积，再取绝对值并除以训练阈值。deviation_ratio大于1告警，连续一致性分数为exp(-0.5×ratio²)。

默认选择在本次test运行前冻结，依据是单通道可解释性、缺失隔离及较少牵连；**不表示全场景F1最高**。演示模型预先选seed42，未从测试中挑选种子。条件EWMA与两种逐点评分作为固定对照保留。SMA、CUSUM、carry仅保留研究实现和历史证据。

序列边界、可见工况改变及缺失会重置相应记忆。未知工况不可评分；边际方法单通道缺失只影响该通道，条件方法需要完整输入行。分数不是测量正确概率、产品质量或安全合格率。

### 3.3 可复用组件

`src/scoring_component.py`负责模型/数据契约和DataFrame评分，`src/score_batch.py`提供统一CLI，`src/prepare_scoring_demo.py`导出示例。模型JSON检查维度、正尺度/阈值、有限性、协方差正定与精度矩阵一致性。CSV检查严格字段、单位声明、数值、顺序、重复和缺步；不偷偷排序、填补、转换单位或读取质量标签。

输出逐传感器分数、偏离、available、alarm和status；不可评分时alarm为空，避免误作正常。每次调用处理完整序列，不支持跨调用流式状态续接。示例26行输入得到78条传感器记录：74可评分、3条未知工况、1条传感器缺失。详见[使用指南](SCORING_GUIDE.md)。

## 4. 实验推进的完整逻辑

| 阶段 | 回答的问题 | 已得到的结论与限制 |
| --- | --- | --- |
| 历史M0–M4 / E1 | 单一normal参考是否足够 | 旧四变量实验暴露严重合法工况误报；旧经验Q不沿用为真实产品质量 |
| E1b | 分工况与逐传感器参考如何表现 | 建立五种参考/残差基准；条件方法存在干净通道牵连 |
| E1c | 弱偏置、多通道、记录延迟会怎样 | 弱偏置漏检；条件法中等偏置有收益、强偏置牵连明显；延迟记录引起误报；比例和时长混杂已记录 |
| E1d | 因果EWMA能否改善持续偏置 | 局部改善检出，同时增加响应延迟和告警拖尾 |
| E1e | 完整9步SMA能否减少拖尾 | 未达到目标，20组全时间轴F1/Recall均低于EWMA，不采用 |
| E1f | 独立控制事件时长/数量/起点，CUSUM是否更好 | 完成12类受控场景；固定CUSUM的24组F1均低于EWMA，不升级默认 |
| E1g | 记录改变时是否应保留历史 | carry改善跨切换检出，但延迟记录恢复后误报严重；保留reset |
| v0.1收尾验收 | 冻结组件在原保留序列能否运行、边界是否仍存在 | 四种固定方法、五种子、十二场景完整评价；低召回、拖尾、延迟记录风险仍在 |

因此当前共有**六轮储运开发实验E1b–E1g**，另有历史E1和本次最终验收。本轮不是新增E1h，也不以实验数量作为完成标准。每轮方法与结果文档在docs/METHOD_LOGISTICS_*和docs/RESULTS_LOGISTICS_*，原始产物在results对应目录。

### 5.3 必须同时看到的比较和失败

- 基准弱偏置：边际EWMA F1 0.2152，高于边际逐点0.1235；条件EWMA为0.4181，说明默认方法并非检测F1最优。
- 短4步弱偏置：边际EWMA F1 0.0527，低于边际逐点0.0815；跨切换前6步也是EWMA较弱的场景。
- 强4倍偏置：边际逐点F1 0.8713，高于边际EWMA 0.6648；后者事件后12步误报41.18%，存在明显拖尾。
- 同一强偏置场景，条件EWMA对污染行中干净通道的牵连FPR为41.81%，边际EWMA为1.08%。因此不能只凭条件法弱偏置Recall更高就将它作为普遍默认。
- 完全clean轨迹上，默认方法稳态FPR为1.71%±0.96%，即时工况切换为1.51%±0.81%，延迟12步升至8.39%±0.48%；延迟场景真实转场后12步窗口为54.77%±1.46%。名义q99并不保证部署误报为1%。
- 默认方法基准事件的新告警检出率45.00%；已检出事件平均延迟5.71步，把漏检按12步惩罚后平均9.18步。仅报已检出延迟会掩盖漏检。

结论：本次完成了组件功能验收和性能边界记录，**没有解决所有弱污染和工况延迟问题**，也没有在看到test结果后更换默认参数。全部对照、逐状态标准差和有效seed数见summary.csv、event_summary.csv。

## 8. 仍存在的问题及优先级

| 优先级 | 问题 | 当前处理 |
| --- | --- | --- |
| 高：进入真实阶段前 | 产品/监测位置/单位/采样/可信历史不明确 | 冻结v0.1，等待最小数据说明；禁止直接套用示例阈值 |
| 高：若开展质量预测 | 质量标签、取样/报告/预测时间未定义 | 先冻结任务，再确定按到货或抽检预测，不能制造逐步标签 |

| 中：后续数据适配 | 不规则采样、传感器漂移、未知工况和可靠训练片段 | 真实数据到位后按实际问题另立适配协议 |
| 中：研究外推 | abrupt转场、单通道最终偏置、同族模拟数据 | 记录覆盖边界；暂不新增无目标模拟实验 |

## 10. 接下来的推进方式

1. 当前版本收尾后冻结方法与实验，不等待几天的数据回复而继续增加检测器。
2. 用户与导师确认场景/数据字典/少量样例；确定下一阶段优先做真实评分验证还是质量预测。
3. 数据到位后先做可用性审查：单位/时序/任务划分/记录可用时间/标签支持。形成单独数据接入协议，再决定代码改动。
4. 若支持质量预测，先线性/PLS及普通LSTM，在相同预测器下公平比较观测、观测+工况、观测+工况+评分；不把模拟检测收益预设为预测收益。

当前用户无需立即补齐数据才能结束v0.1。需要未来决定的是实际产品与用途、能提供哪些字段、是否有质检标签。此前实验、负面结果和全部历史文档均保留，便于随时恢复下一阶段。
