# E1e：有限记忆与覆盖率对照

## 研究问题
E1d的条件EWMA改善部分持续偏置检出，但强偏置结束后的拖尾明显。E1e只替换时间汇总方式，比较逐点、alpha=0.2 EWMA和完整9步有符号简单滑动均值（SMA）。两个残差参考均保留，不同时加入修复、状态估计或质量预测。

## 定义与预设窗口
对E1d相同的有符号标准残差u，h(t,j)=sum(u(t-k,j), k=0..W-1)/W。绝对值在平均后计算。W=9，未依据本轮验证表现选窗口。

[NIST给出的EWMA递推](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc324.htm)对应稳态几何权重alpha*(1-alpha)^k。由权重求和可得：独立等方差输入下方差倍率为alpha/(2-alpha)，平均样本年龄为(1-alpha)/alpha。SMA分别为1/W和(W-1)/2。alpha=.2与W=9在这两项上均相同（1/9、4步）。这是本项目的解析选值依据；当前数据有时间相关性，不能据此宣称两者实际方差、延迟或误报完全匹配。

每条序列、可见工况记录改变或通道残差缺失后，必须重新积满9个连续可用残差。未积满时返回NaN、available=false、alarm=false；false不表示可靠。条件残差一通道缺失导致整行不可用；未知工况不可评分。没有零填充或部分窗口，也不按隐藏真工况/污染事件重置。W=1退化为逐点残差。

污染在某通道残差中的直接历史贡献，在其最后一个受影响残差退出窗口后消失；这不保证此后零告警，因为仍有噪声、参考偏差或其他通道污染。

## 校准与数据
只复用E1c完整序列划分；参考来自train_fit，SMA阈值来自train_cal中完整窗口abs(h)的逐状态/逐通道q99。原E1d逐点和EWMA评分从存档原样读取，先审核E1c与E1d全部产物hash及二者来源对应。基线不受依赖升级后的重新拟合影响。所有阈值为相同名义分位数，不是严格匹配验证FPR。
5种子42–46、原10场景均保留，test不评价。输出新SMA分数与模型，旧基线通过输入manifest引用，不复制数据。

## 公平评价
| 口径 | 分母与含义 |
| --- | --- |
| common | 同一视图下6种评分均可用的完整行，逐点F1/AP/Recall和FPR比较用完全相同单元 |
| own | 各方法自己的完整可评分行，须与native_score_coverage一起解读 |
| all_timeline_recall/f1 | 原全时间轴，未评分污染点计未检出，不能因丢弃启动区间而获益；不把未评分当作已判可靠 |
| unavailable_positive_fraction | 所有污染单元中不可评分的比例 |
| 事件指标 | 所有注入块-通道均保留，未评分不剔除；新告警/延迟/截断延迟沿用E1d，增加scoreable_fraction与fully_unavailable |
| post_event_fpr | 同E1d事件后12步的去重干净单元，在common/own完整行支持上分别计算 |

全时间轴指标会在两种support行中重复，必须读取一次，不能当独立重复证据。事件只在原时间轴算一次，绝不把删减后的时间轴用于延迟或告警起点。clean副本同样评价用于对照巧合告警。先逐seed汇总，再报告样本标准差；保存SMA减EWMA和SMA减逐点的配对差，不选最好种子。共同支持只解决评价分母不同，不能抹除实际启动期盲区。

## 产物与运行
配置configs/logistics_e1e.yaml，运行：
```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m src.run_finite_memory_e1e --config configs/logistics_e1e.yaml
```
结果包含新SMA分数、模型和校准审计、逐种子分层表、全事件表、均值/标准差、配对差、PNG/PDF图、输入和产物hash、源码提交与环境。方法章对应时间汇总/不可用定义；实验章对应记忆方式与覆盖消融；讨论对应盲区和尾部权衡。经典SMA本身不是首创，检测实验不能证明质量预测增益。
