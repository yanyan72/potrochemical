# 唯一候选的开发验证协议

2026-10-29。承接第一周固定阈值参考替换诊断：参考替换有方向性依据，但新候选尚无性能证据。本协议在候选首次正式开发评价前提交。主动提前执行第二周任务，不等待日历到第二周。

## 固定范围

只评价已提交的 shared_mode_fault_reference_v1，κ=4、12状态、故障先验和转移均保持首版设置。保留两个预定消融：κ=0、无故障状态记忆。**只有 joint_full 能作为本轮候选通过，事后不把更好的消融切换成新主方法。** 三组不进行超参数搜索。

数据复用 A0 的全部360批、六配对视图；真工况仅用于评价，不输入候选。模型使用 A0 已存正常参考和模式转移。校准仍使用旧 reference_cal，无故障的正确/延迟12两版本等权、每通道99%分位；α=.2、按可见记录变化重置，CDF截断保持1e−12。模型只读取可见观测和记录；不读质量标签。保存所有train/val、种子、通道、相位结果。

软件必须验证：κ=0的工况后验、阈值和告警重放与原soft_all一致。若不一致先排查实现，不将差异当机制收益。原数据、A0模型和全部结果保持只读。

## 先冻结的开发推进门槛

以下仅为进入最多21次预测开发拟合的项目筛查标准，不是显著性结论，也不是工业验收标准。主判断仅用已使用过的开发val。

1. 在correct_bias4和delay12_bias4两个视图，joint_full正常通道FPR各自三个种子均低于soft_loo，平均相对下降至少50%；可归因事件检出各自每个种子相对soft_loo降低不超过5个百分点。
2. 正确/延迟无故障场景FPR每个种子均≤1.5%，且相对soft_all增加不超过0.5个百分点；两个强偏置场景正常通道FPR每种子≤3%。
3. 机制相对经典soft_all要有额外价值：两个强偏置场景中，振动故障的可归因事件检出平均提升至少5个百分点；温度、湿度任一种子/记录条件的事件检出不得下降超过5个百分点。
4. 弱漂移、训练描述、所有消融全部公布，不以未通过的主条件换取某一有利子组。通过上述三项才开启预测开发；若未通过，不启动21次拟合，不调参数再试，不提升消融为新主方法。

A0旧协议要求相对硬组的正常FPR增量小于0.5个百分点；该硬组因校准延迟而在正常场景特别保守。**本新协议明确调整为绝对风险上限加相对soft_all约束，属于知晓A0后的新开发决策，不改写A0失败。** 1.5%/3%等数值是本项目预先设定的筛查容差，后续不能表述为现场安全阈值。

## RQ3边界与预算

即使本开发筛查通过，RQ3仍未获支持；它只授权固定七组、三个数据种子、单优化种子的21次预测开发。主组仍为NG，须同时优于N和RG且符合四周计划中的开发效应/正常风险条件，才有后续70次确认拟合。不得因评分改善而跳过预测对照。

如果本轮失败，报告实际机制与负结果，按限期计划收尾必要的RQ1确认和证据包，交导师判断创新性；不继续无限探索。所有代码、设置、结果和失败一并上传原始项目。
