# Codex Execution Plans

复杂功能、跨模块修改、科学方案变更或预计超过一小时的工作必须使用 ExecPlan。

## ExecPlan 必须自包含

读者只拥有当前工作树和这一份计划，也能理解并继续工作。不要依赖上一次聊天记忆。

## 必须包含的章节

### Purpose

说明用户最终会获得什么可观察结果，以及为什么重要。

### Current state

列出现有代码、数据、文档和已知限制。不要假设仓库为空。

### Scientific assumptions

列出所有建模假设、单位、数据来源、标签定义和不能证明的事项。

### Scope

明确本计划包含与不包含的内容。

### Milestones

将工作拆成可独立验证的里程碑。每个里程碑都必须有：

- 输入；
- 修改文件；
- 输出；
- 运行命令；
- 测试；
- 验收标准。

### Data leakage controls

说明训练、验证、测试如何划分；哪些统计量只能在训练集拟合。

### Reproducibility

说明随机种子、配置、数据版本、代码版本和结果保存方式。

### Validation

列出单元测试、集成测试、烟雾实验和人工检查。

### Progress

使用复选框持续更新：

- [x] 已完成项，附时间和结果；
- [ ] 未完成项；
- 失败尝试必须保留。

### Decision log

记录每项重要决策、替代方案和原因。

### Surprises and discoveries

记录实现过程中与原假设不一致的现象。

### Outcomes and retrospective

结束时总结：

- 实际交付；
- 是否满足验收；
- 未解决问题；
- 后续建议。

## 执行原则

- 先写计划，再实现。
- 计划是活文档，每个停止点都更新。
- 不因小歧义停止；采用可配置、可回退的保守假设。
- 不伪造执行结果。
- 遇到方法不可行时，先做最小原型验证，再调整计划。
